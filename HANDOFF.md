## Known limits and ideas for later

- **Orion Store screenshots need a manual update.** Orion shows screenshots through an image cache that keeps each address for 31 days, so changing the pictures in `docs/screenshots/` never reaches it. Its listing uses addresses pinned to a commit (since 2026-11-22: the merge of the pull request that added the Summit and Focus Sky screenshots; eight pictures, the most striking first). Whenever the screenshots change, send Orion new pinned addresses (YouDO → ⋮ → Request app change → Screenshot URLs). The steps are in [RELEASE_PROCEDURE.md](RELEASE_PROCEDURE.md) under "Orion Store screenshots".

- **Edits made elsewhere.** The widgets cannot see changes made on another device (such as the website) while the phone app is closed. Fixing it would mean fetching from Supabase in the background (for example WorkManager plus the stored widget key). That is a bigger piece of work, so it was left for later.
- **Average and streak.** The widget's 30-day average and the streak count refresh only when the app opens.
- **No local Android build.** The Android code cannot be compiled on the Windows PC; the CI build is its first compile. Run a test APK from Actions when Java changes are risky.
- **Bundle budget.** The first-load JavaScript is close to its gzip budget (`npm run verify:build`), so new first-screen code should be lazy-loaded.
- **Releasing from the browser pane (learned with v9.1.0).** The pane can't download files: the owner clicks **Download YouDO-APK** on the Actions run, then the zip is unzipped into its own folder (`Downloads\YouDO-vX.Y.Z`), checked (package `com.mattedhairr.youdo`, the new versionName in the manifest) and renamed `YouDO.apk`; the owner drags it onto the release page, then it is checked (one asset, `YouDO.apk`) and published. The pane's GitHub sign-in can drop when the pane restarts; the owner signs in again. The APK build sometimes fails on Maven Central's "429 Too Many Requests" (v9.0.0 and a v9.1.0 branch build): not the code, re-run it.
- **Retaking screenshots.** Local only (`docs/mocks/` is never committed, so these may need rewriting): `docs/mocks/zz-shot.html` runs the real app with made-up data (`shot-seed.js`), a set clock and `?view=&time=&accent=&w=&long=`, and slides away the day's briefing; `zz-phone.html` frames it 412 px wide. Capture with headless Edge in an empty profile (never the pane: the seed clears local storage), crop to the frame, then `node scripts/frame-screenshots.mjs docs/screenshots <name>=<capture>`.

## How to resume

```bash
git checkout main
git pull --ff-only
npm ci
```

Then:
1. Copy `.env.example` to `.env` and fill it in from the Supabase dashboard → Project Settings → API (URL and anon key).
